# 프로젝트 기본 작업환경 설계

## 배경

현재 프로젝트를 등록하면 프로젝트 레코드만 생성된다. 사용자는 별도 Git worktree를 만드는 에이전트를 추가하기 전까지 터미널과 파일 작업 화면을 열 수 없다.

프로젝트 등록 직후 기존 프로젝트 디렉터리를 그대로 사용하는 첫 작업환경을 만들어, worktree 생성 없이도 현재 체크아웃에서 바로 에이전트를 실행할 수 있게 한다.

## 목표

- 프로젝트 등록 시 첫 작업환경을 함께 생성한다.
- 첫 작업환경은 별도 worktree를 만들지 않고 등록한 프로젝트 디렉터리를 사용한다.
- 프로젝트 추가 창에서 첫 작업환경의 에이전트 종류를 선택한다.
- 저장소의 checkout 상태나 파일을 변경하지 않는다.
- 프로젝트와 첫 작업환경을 원자적으로 저장해 불완전한 프로젝트가 남지 않게 한다.
- 기존의 새 worktree 생성과 작업환경 공유 흐름을 유지한다.

## 비목표

- 프로젝트 등록 시 기본 브랜치로 자동 checkout하지 않는다.
- 에이전트별 기본 실행 명령 설정 기능을 새로 만들지 않는다.
- 기존 프로젝트에 누락된 기본 작업환경을 자동으로 소급 생성하지 않는다.
- 데이터베이스 스키마를 변경하지 않는다.

## 사용자 흐름

1. 사용자가 프로젝트 추가 창에서 이름과 로컬 저장소 경로를 지정한다.
2. 사용자가 첫 작업환경에서 실행할 에이전트 종류를 선택한다.
3. 앱이 경로와 Git 상태를 검증한다.
4. 앱이 프로젝트와 `기본 작업환경` 에이전트를 함께 저장한다.
5. 앱이 새 작업환경을 선택해 기존 프로젝트 디렉터리에서 터미널을 연다.
6. 이후 사용자는 기존과 동일하게 별도 worktree를 만들거나 기존 작업환경을 공유하는 에이전트를 추가할 수 있다.

## 데이터 모델

기존 `Project`와 `Agent` 모델을 그대로 사용한다.

기본 작업환경 에이전트의 필드는 다음과 같다.

| 필드 | 값 |
|------|----|
| `title` | `기본 작업환경` |
| `kind` | 프로젝트 추가 창에서 선택한 에이전트 종류 |
| `command` | 선택한 종류의 기존 기본 실행 명령 |
| `branch` | 등록 시점에 프로젝트 디렉터리에 실제로 checkout된 브랜치 |
| `worktreePath` | 정규화한 프로젝트 디렉터리 경로 |
| `worktreeManaged` | `false` |

`worktreeManaged=false`이므로 에이전트나 프로젝트를 삭제해도 원본 프로젝트 디렉터리는 제거 대상이 아니다.

## 백엔드 설계

### Git 검증

Git 모듈에 프로젝트 작업환경 정보를 조회하는 함수를 둔다.

- 입력 경로를 정규화한다.
- 해당 경로가 Git 작업 트리인지 확인한다.
- 현재 checkout된 브랜치를 읽는다.
- detached HEAD이면 기본 작업환경을 안정적으로 표시하고 공유할 브랜치명이 없으므로 명확한 오류를 반환한다.
- 브랜치를 checkout하거나 작업 파일을 수정하지 않는다.

사용자가 말한 “기본 브랜치”는 별도 worktree가 아닌 프로젝트의 기본 작업 디렉터리를 뜻한다. 실제 브랜치 표시는 안전을 위해 등록 당시 현재 checkout된 브랜치를 사용한다.

### 원자적 생성

프로젝트와 기본 작업환경을 함께 생성하는 전용 명령을 추가한다.

1. DB 락 밖에서 Git 경로와 브랜치를 검증한다.
2. 짧게 DB 락을 잡는다.
3. 하나의 SQLite 트랜잭션에서 프로젝트와 에이전트를 삽입한다.
4. 에이전트가 포함된 `Project`를 반환한다.

두 레코드 중 하나라도 저장에 실패하면 전체 트랜잭션을 롤백한다.

기존 `create_project`와 `create_agent` 명령은 기존 호출과 worktree 생성 흐름을 위해 유지한다.

## 프런트엔드 설계

### 프로젝트 추가 창

- 기존 이름·경로 입력 아래에 에이전트 종류 선택을 추가한다.
- 종류별 표기와 기본 명령은 기존 `agentKindLabels`, `agentKindDefaults`를 재사용한다.
- 제출 중 중복 제출을 막는다.
- Git 검증 또는 저장 실패 메시지를 다이얼로그 안에 표시하고 입력값을 유지한다.

### 프로젝트 저장소와 선택

- 프로젝트 저장소의 프로젝트 추가 동작은 새 원자적 IPC를 호출한다.
- 반환된 프로젝트에는 기본 작업환경 에이전트가 포함된다.
- 성공한 작업은 로컬 프로젝트 목록에 한 번만 추가한다.
- 프로젝트 추가 창은 반환된 기본 작업환경을 `shell.selectAgent`로 선택한 뒤 닫는다.

### 기존 에이전트 추가

기존 에이전트 추가 창의 동작은 유지한다.

- 새 worktree 만들기
- 기존 에이전트의 작업 디렉터리 공유

기본 작업환경도 일반 에이전트와 같은 모델이므로 기존 공유 목록에 나타나며, 공유 시 프로젝트 디렉터리를 그대로 재사용한다.

## 오류 처리

- 존재하지 않는 경로: 프로젝트를 생성하지 않고 경로 오류를 표시한다.
- Git 작업 트리가 아닌 경로: 프로젝트를 생성하지 않고 Git 저장소가 아니라는 오류를 표시한다.
- detached HEAD: 프로젝트를 생성하지 않고 브랜치 checkout이 필요하다는 오류를 표시한다.
- DB 실패: 프로젝트와 기본 작업환경을 모두 롤백한다.
- 프런트엔드 실패: 다이얼로그를 유지하고 재시도할 수 있게 한다.

어떤 오류에서도 checkout, worktree 생성, 디렉터리 삭제를 수행하지 않는다.

## 테스트 전략

### Rust

- Git 저장소 경로를 정규화하고 현재 브랜치를 반환한다.
- Git 저장소가 아닌 경로를 거부한다.
- detached HEAD를 거부한다.
- 프로젝트와 기본 작업환경을 한 트랜잭션으로 저장한다.
- 기본 작업환경은 프로젝트 경로를 사용하고 `worktreeManaged=false`이다.
- 저장 실패 시 프로젝트만 남지 않는다.
- unmanaged 에이전트 삭제가 원본 디렉터리를 제거하지 않는 기존 조건을 유지한다.

### TypeScript/Svelte

- 프로젝트 저장소가 새 IPC의 프로젝트와 기본 작업환경을 목록에 반영한다.
- 프로젝트 추가 창에서 선택한 종류와 대응 기본 명령을 전달한다.
- 생성 성공 시 기본 작업환경을 선택한다.
- 생성 실패 시 입력과 오류 상태를 유지한다.

### 회귀 검증

- 기존 TypeScript 단위 테스트와 Svelte 정적 검사를 실행한다.
- Rust 단위 테스트와 Clippy를 실행한다.
- 새 worktree 생성, 공유 worktree 재사용, managed worktree 삭제 테스트가 계속 통과하는지 확인한다.

## 완료 조건

- 새 Git 프로젝트를 등록하면 프로젝트 목록에 `기본 작업환경`이 즉시 나타난다.
- 해당 작업환경을 열면 등록한 프로젝트 디렉터리에서 선택한 에이전트 명령이 실행된다.
- 프로젝트 등록 과정에서 새 worktree나 branch checkout이 발생하지 않는다.
- 기본 작업환경 또는 프로젝트를 삭제해도 원본 프로젝트 디렉터리는 삭제되지 않는다.
- 프로젝트와 기본 작업환경이 항상 함께 생성되거나 함께 롤백된다.
